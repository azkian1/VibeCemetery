# REKT: подтверждение аккаунтов Privy, FOMO и Axiom

Проверено 9 сентября 2026 года. Исследование публичной документации и публичной конфигурации веб-приложений. Вход в пользовательские аккаунты, создание аккаунтов, подписи, переводы и обращения к командам не выполнялись. Принятые после исследования продуктовые решения отмечены ниже и внесены в основной план; код авторизации не изменён.

## Результат

**Продуктовое решение после исследования, 9 сентября 2026:** для FOMO пользователь выбрал привязку через личный кошелёк первого пополнения торгового баланса. Этот кошелёк подписывает сообщение, сервер проверяет первенство пополнения и сохраняет отдельный метод `first_funding_source`. Он достаточен для права создания REKT при остальных выполненных проверках. Риск первого пополнения другим человеком принят; подпись FOMO, экспорт ключей и Global Wallets для этого пути не требуются. Публичная формулировка: `Initial funding source verified`. Решение зафиксировано в основном локальном плане, раздел 3.2.1; реализация ещё не выполнена. На Axiom оно автоматически не распространяется. Ниже сохраняются результаты исследования прямой авторизации.

**Уточнение сетей источника:** Base, Robinhood Chain, BNB Chain и Ethereum mainnet. Проверяется первое значимое пополнение торгового баланса среди сетей, с учётом межсетевых маршрутов; оно может происходить в другой сети, чем выбранная история убытка. Принят минимальный порог $10 на один перевод по исторической цене. Меньший перевод перед крупным от того же источника сохраняется как возможный пробный, не перенося приоритет назад. Повторные значимые пополнения усиливают связь, сохраняя требование первого источника и его подписи. Неполное покрытие не позволяет объявить поздний платёж первым. Это требование к привязке FOMO, а не добавление BNB/Ethereum в область расчёта PnL. Подробный контракт и приёмочные сценарии обновлены в разделе 3.2.1 основного плана.

| Объект | Подтверждено | Статус для REKT |
| --- | --- | --- |
| Privy Global Wallets | Передача проверенной связи пользователя с адресами между приложениями; предусмотрен режим read-only | Подходящая инфраструктура, но приложение-источник должно стать провайдером и разрешить подключение |
| FOMO | Использует Privy; публичное веб-приложение содержит реальный Privy App ID | Доступность Global Wallet для стороннего REKT не подтверждена. Рабочий вход без экспорта ключей не продемонстрирован |
| Axiom Trade | Использует Turnkey; предлагает регистрацию через email, Google и Phantom | Публичный внешний коннектор/OAuth для подтверждения торговых адресов Axiom не найден. Это не утверждение об отсутствии частных партнёрских интеграций |

## Privy: что действительно возможно

Global Wallets позволяет приложению-источнику после согласия пользователя передавать адреса в другое приложение. Read-only режима достаточно для проверки принадлежности: он не разрешает запрашивать подписи или транзакции. Доступ провайдера требует одобрения Privy, настройки домена и включения публикации кошельков. Доступные провайдеры перечислены в авторизованном Dashboard, раздел Global Wallet → Integrations. Этот список в данной проверке не был просмотрен. [Интеграция](https://docs.privy.io/wallets/global-wallets/integrate-a-global-wallet/overview), [настройка провайдера](https://docs.privy.io/wallets/global-wallets/launch-your-wallet/overview).

После подключения появляется связанный аккаунт `cross_app`. У него есть `providerApp.id`, списки `embeddedWallets` и `smartWallets`, даты проверки. Для REKT нужно сопоставлять конкретный адрес сделки с адресами доверенного провайдера; наличие любого связанного кошелька недостаточно. [Структура связанных кошельков](https://docs.privy.io/wallets/global-wallets/integrate-a-global-wallet/getting-global-wallets).

Предлагаемый серверный контракт: проверить сессию своего приложения; получить проверенные сведения о связанном аккаунте; проверить разрешённый provider ID и точный торговый адрес; сохранить метод и время подтверждения. Поля, присланные браузером без серверной проверки, не принимаются. Вход по одному email в два разных приложения сам по себе не создаёт такую связь. [Проверка сессии Privy](https://docs.privy.io/authentication/user-authentication/access-tokens).

## FOMO: проверка сверх документации

Использование Privy прямо указано в [условиях FOMO, раздел 6](https://fomo.family/terms). Публичная страница и загружаемые ею JS-модули также подтверждают использование Privy. Наличие SDK и App ID не означает включённый Global Wallet.

Проверены публичные клиентские модули, доступные через manifest страницы `https://fomo.family`:

- `PublicPrivyProvider-v2-BNvX5Mju.js`: публичный компонент входа с Apple/Google.
- `privy-v2-COjjl0Cs.js`: публичный App ID `cm6h485o300n3zj9yl6vpedq7`.
- `index-C4V-Gi_H-v2-DN3AphRJ.js`: клиентский SDK содержит маршрут чтения `/api/v1/apps/{appId}/cross-app/details`.

Результаты чтения без пользовательских токенов:

| Запрос | Ответ | Что он показывает |
| --- | --- | --- |
| `https://auth.privy.io/api/v1/apps/cm6h485o300n3zj9yl6vpedq7` | HTTP 200, имя `fomo`, custom API `https://privy.fomo.family` | Публичный App ID соответствует FOMO |
| Cross-app details для этого ID через `auth.privy.io` | HTTP 404, `Config not found` | Публичные метаданные подключения не получены |
| Тот же маршрут через `privy.fomo.family` | HTTP 404, `Config not found` | Настроенный домен также не дал подтверждения |
| Контроль: Abstract ID из документации Privy, тот же маршрут | HTTP 404, `Config not found` | Этот способ проверки недостаточен для заключения, что Global Wallet выключен |

Не следует интерпретировать результат как доказанное отсутствие поддержки FOMO. Возможны ограничения контекста запроса, изменения API или частная конфигурация. Подтвердить возможность можно через каталог провайдеров Privy и успешную авторизацию конкретного пользователя либо через ответ команды FOMO.

Общая статья FOMO о подключении dApps объясняет обычные внешние кошельки и не документирует собственный FOMO-коннектор для сторонних сайтов. [Статья FOMO](https://fomo.family/answers/how-to-connect-wallet-to-dapps).

## Axiom: отдельная интеграция

И [FAQ Axiom](https://docs.axiom.trade/faqs), и [кейс Turnkey](https://www.turnkey.com/customers/axiom-global-defi-trading-platform) подтверждают использование Turnkey. Подключение Privy к REKT само по себе не откроет доступ к торговым аккаунтам Axiom.

Официальная [инструкция регистрации](https://docs.axiom.trade/getting-started/signup) описывает email, Google и Phantom, затем восстановление торгового кошелька через recovery phrase. Вход через Phantom не доказывает, что этот же адрес совершал сделки: нужно сравнить адреса либо получить проверяемую связь между аккаунтом и его торговыми кошельками. [Multi-wallet](https://docs.axiom.trade/multi-wallet) также означает, что у одного аккаунта может быть несколько торговых адресов.

В [публичном индексе документации Axiom](https://docs.axiom.trade/llms.txt) и поиске официальных материалов не найден внешний OAuth/коннектор для подтверждения адресов сторонним приложением. Прямой HTTP-запрос главной страницы Axiom в среде исследования вернул 404; действующий интерфейс авторизованного аккаунта не проверен. Документация может отставать от продукта, поэтому отсутствие найденного описания не равно доказанному отсутствию функции.

Turnkey предоставляет средства авторизации, но их использование приложением не создаёт автоматического доступа к аккаунтам другого приложения. Возможность партнёрской авторизации должен предоставить сам Axiom. [Авторизация Turnkey](https://docs.turnkey.com/features/authentication/overview).

## Следующее проверяемое действие

1. **FOMO / Privy:** проверить FOMO в Global Wallet → Integrations и возможность read-only подключения. Нужны production provider ID, разрешённый requester и проверенные EVM/Solana адреса после входа. Если нет публичного провайдера, запросить у FOMO возможность включения read-only режима.
2. **Axiom:** выяснить наличие внешнего OAuth, wallet connector или подписанного подтверждения «аккаунт → торговые адреса». Подтверждение должно быть привязано к нашему приложению и пользовательской сессии, иметь срок действия и защиту от повторного использования.
3. **Приёмка:** на отдельном тестовом аккаунте пройти подключение без экспорта ключей; сервером подтвердить точный адрес; проверить отказ для чужого адреса, неподходящего провайдера, просроченной сессии и отозванной связи. Только после этого показывать соответствующую кнопку входа пользователям REKT.

До такой проверки прямая авторизация FOMO/Axiom остаётся неподтверждённой. Для FOMO принят отдельный путь через первое пополнение, описанный выше; его реализация не зависит от наличия Global Wallets. Сам публичный скан адреса не предоставляет права создать могилу от его имени. Поддержка авторизации не заменяет отдельную проверку PnL и покрытие сетей; текущий сканер не имеет полноценного адаптера истории Solana для Axiom.

Точные вопросы командам (черновики, не отправлены):

- **FOMO:** “Does FOMO expose its existing trading wallets through Privy Global Wallets in read-only mode? We only need authenticated ownership of the user's exact EVM/Solana trading addresses. Can a third-party requester integrate today, and what provider app ID and approval process should it use?”
- **Axiom:** “Do you offer an official third-party login or wallet connector that proves ownership of an account's trading wallet addresses without exporting keys? We need an audience-bound, verifiable address assertion, not transaction permissions. Does Phantom login expose such a verified association with Axiom-created wallets?”
