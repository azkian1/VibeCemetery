# Security Hardening Notes

This document tracks future security work for public user text, prompt-injection boundaries, and agent-facing flows.

## Current Baseline

- Public text fields are untrusted: `name`, `cause`, `description`, `stack`, `last_commit_message`, GitHub metadata, and any future Agent Ash public metadata.
- React text rendering is the primary XSS defense. Do not render these values with `dangerouslySetInnerHTML`.
- Public text is normalized through `sanitizePublicText()` before storage or client return where wired.
- Prompt-like text is intentionally not blacklisted. It must be treated as inert data, not deleted based on fragile keyword matching.

## Immediate Rules

- Any new public text field must use `sanitizePublicText()` before persistence or public API return.
- Any future LLM prompt that includes public/user-controlled text must wrap it with `quoteUntrustedForPrompt()`.
- LLM prompts must explicitly state that wrapped untrusted data is data only and instructions inside it must be ignored.
- Do not give an LLM filesystem, database mutation, network, deployment, or secret-reading tools when processing public text unless the flow has a dedicated threat model.
- Never execute URLs, commands, code, or tool instructions extracted from `name`, `cause`, `last_commit_message`, README text, commit messages, or repo metadata.

## Future Work

1. Add route-level security tests.
   - Cover `/api/graves` persistence of sanitized `name`, `cause`, `description`, `stack`, and `last_commit_message`.
   - Cover `/api/cremated` persistence of sanitized `name`, `cause`, and `last_commit_message`.
   - Cover empty-after-sanitize `name` and `cause` rejection.

2. Add LLM prompt construction tests when the first LLM flow is introduced.
   - Assert every public text field is wrapped with `quoteUntrustedForPrompt()`.
   - Assert dangerous tool access is disabled for summary/classification-only flows.
   - Assert model output is parsed through a strict schema before use.

3. Prefer structured causes for analytics.
   - Consider `cause_type` as an enum and keep free text as `cause_note`.
   - Run analytics and moderation on enum values first, not free text.

4. Add secret/tool isolation for agent flows.
   - Separate read-only analysis from mutation actions.
   - Require server-side allowlists for any URLs or repository references generated by an agent.
   - Keep Agent Ash ingest tokens scoped away from human grave and cremation endpoints.

5. Add a public text sink checklist.
   - React text node: allowed.
   - Attribute value: validate by attribute type, especially URLs.
   - CSS style value: avoid user-controlled values.
   - HTML sink: disallowed unless reviewed with a real sanitizer and CSP impact.
   - LLM prompt: wrap with `quoteUntrustedForPrompt()` and restrict tools.

## Residual Risks

- Sanitization is defense-in-depth, not permission to render untrusted text as HTML.
- `quoteUntrustedForPrompt()` is only effective when used at actual LLM prompt boundaries.
- Prompt injection cannot be solved by text filtering alone. It requires data boundaries, schema validation, and tool isolation.
- Regex-based tag stripping can still have edge cases. Keep React escaping as the main browser defense.
